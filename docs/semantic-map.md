# Semantic map: главная страница Recipes

Цель карты — отделить смысловые части страницы от визуальных контейнеров Figma и заранее определить семантику HTML.

| Блок макета | Назначение | HTML | Обоснование |
| --- | --- | --- | --- |
| Верхняя область с брендом и навигацией | Вводная часть страницы и глобальная навигация | `<header>` + `<nav>` | Это повторяющаяся верхняя часть сайта с переходами по основным разделам. |
| Бренд Recipes | Ссылка на главную страницу | `<a>` | Логотип/название ведёт на главную, поэтому это ссылка, а не заголовок. |
| Главное меню | Переходы «Главная», «Рецепты», «Избранное» | `<nav>` + список ссылок | Это набор основных навигационных ссылок сайта. |
| Hero «Готовь и делись рецептами» | Объясняет ценность сервиса и содержит главное действие | `<section>` | Самостоятельный вводный смысловой блок. Единственный `<h1>` находится здесь. |
| Кнопка/ссылка «Добавить рецепт» | Целевое действие — перейти к добавлению рецепта | `<a>` | Действие меняет страницу/состояние приложения, поэтому на статическом этапе оформляется как ссылка на будущую страницу/раздел. |
| «Войти» | Переход к авторизации | `<a>` | Это навигационное действие, а не отправка формы на текущей странице. |
| «Умная сортировка по тегам» | Объясняет способ группировки и поиска рецептов | `<section>` | Блок имеет собственный заголовок и отдельную тему. |
| Четыре категории | Самостоятельные повторяющиеся смысловые сущности | список `<ul>` с `<li>` | Это однородный набор категорий; отдельный `<article>` не обязателен, потому что карточки здесь не являются самостоятельными публикациями. |
| Блок с тыквенным супом | Рекомендуемый рецепт с изображением, названием и описанием | `<article>` | Рецепт является самостоятельной сущностью, которая может существовать и быть открыта отдельно. |
| Фото рецепта | Содержательное изображение блюда | `<img>` | Изображение помогает понять, какое блюдо представлено, поэтому нужен осмысленный `alt`. |
| «Поиск рецептов» | Поиск блюда по названию | `<section>` + `<form>` | В макете это самостоятельный блок с полем ввода и кнопкой отправки. |
| Поле «Название блюда» | Ввод поискового запроса | `<label>` + `<input type="search">` | Нативное поисковое поле соответствует назначению данных и должно иметь связанную подпись. |
| Кнопка «Поиск» | Отправка поисковой формы | `<button type="submit">` | Это действие формы, поэтому используется кнопка. |
| Нижняя область с брендом и copyright | Завершающая информация сайта | `<footer>` | Повторяющаяся нижняя часть страницы с информацией о проекте. |

## Спорные решения

### Категории: `section`, `article` или список

Вся группа категорий относится к одному тематическому разделу «Умная сортировка по тегам», поэтому внешний контейнер — `<section>`. Отдельные категории не являются самостоятельными публикациями и не требуют `<article>`; логичнее представить их как элементы списка.

### Рекомендуемый рецепт: `article`

Блок «Тыквенный супчик на кокосовом молоке» содержит самостоятельный объект контента — рецепт. Он имеет собственное название, описание, изображение и автора, поэтому `<article>` отражает смысл точнее, чем обычный `<div>`.

### Визуальные обёртки Figma

Frame, Rectangle и технические группы, используемые только для позиционирования, теней, фоновых волн и декоративных иконок, не переносятся в HTML как отдельные семантические элементы. При необходимости для будущего CSS могут появиться технические `<div>`, но только когда они реально понадобятся для раскладки.
