# Pixel Perfect: приведение главной страницы к макету

Ветка: `fix/figma-pixel-perfect` (от `main` после практики №4, до начала практики №5).

## Что считалось эталоном

1. **Figma, фрейм «Recipes – Главная» (node `9:2`, 1440×2719)** — размеры, отступы, типографика, тексты.
2. **Исходный проект `ProjectExampleJSFull.zip`** — приёмы вёрстки и ассеты (волны, текст по дуге, «+» в кнопке, расположение счётчиков).
3. **Критерии практик №1–4** — если приём архива им противоречит, оставлено решение практик. Каждое такое место описано ниже.

Структура проекта, БЭМ-классы и семантика, принятые в PR #3–#6, не менялись. JavaScript (практика №5) не добавлялся.

## Как проверено

- Скриншот страницы в Chromium с viewport 1440px наложен на экспорт фрейма Figma той же ширины.
- Высота страницы: макет — 2719px, вёрстка — 2719px (до правок было 3209px).
- Пикселей с заметным отличием (сумма разницы RGB > 30): было 27.2%, стало 1.7%. Остаток — сглаживание текста и места, перечисленные в разделе «Известные расхождения».
- Bounding box 15 текстовых блоков (логотипы, меню, h1, лиды, карточки, рецепт, поиск, теги, footer) совпадает с макетом в пределах ±2px.
- Ширины 360, 390, 600, 768, 895, 896, 1024, 1280, 1440, 1920: `scrollWidth === clientWidth`, горизонтального overflow нет.
- Long-content test: длинные заголовки hero, карточки и рецепта на 390 и 1440 не вызывают overflow, счётчики не наезжают на бейдж.
- Клавиатура: Tab проходит логотип → меню → «Войти» → кнопки hero → `@glazest` → поле поиска → «Поиск» → логотип footer; у каждого элемента виден `:focus-visible`, ни один не перекрыт header или счётчиками.
- Nu HTML Checker (`vnu.jar`, локально): 0 ошибок, 0 предупреждений.
- CSS: `vnu.jar --css` и `csstree-validator` — 0 ошибок (`normalize.css` не проверялся как vendor-файл).

## Решения: архив → что сделано → почему → как можно было иначе

| Блок | В архиве | Сделано | Почему | Альтернатива |
| --- | --- | --- | --- | --- |
| Header | `position: fixed`, появление через `@keyframes`, фон по скроллу добавляет JS (`header--scroll`) | С 56rem `position: absolute` поверх hero, ниже 56rem — обычный поток | Фон по скроллу требует JS (практика №5); fixed-header без фона перекрывал бы контент при прокрутке. `@keyframes` в практике №4 не требуются | В практике №5 вернуть `fixed` и класс-модификатор по событию `scroll`, как сценарий №1 архива |
| Фото hero | `img` с `position: absolute; top: 0; right: 0` внутри `.container` 1440px, у контента фиксированные `margin-top: 211px; margin-bottom: 239px` | Grid `688fr / 602fr` в области шириной до 1440px; левая граница контента совпадает с контейнером 1200px, фото в потоке | Высота hero зависит от контента, нет «магических» margin; на 896–1440 колонки сжимаются пропорционально (практика №4: fluid, без фиксированной desktop-ширины) | Вариант архива даёт тот же результат на 1440, но на промежуточных ширинах контент может заехать под фото, и нужны отдельные правила (в архиве — `max-height: 500px` на 1024) |
| Волны | `wave1.png`, `wave2.png` лежат в `images/`, но в CSS не подключены | Фон `.page` с 56rem: две PNG, `top` = 90px и 1143px (подобрано сравнением с экспортом Figma), `background-size: max(100%, 1440px) auto` | Волны декоративные: в HTML их нет, только CSS. На узких ширинах страница в 1.5 раза выше, и фиксированные отступы попадали бы мимо секций — там волны выключены | Привязать волны к секциям через `::before` (устойчивее к длине контента) или экспортировать SVG-векторы из Figma |
| Бейдж «рецепт дня» | SVG `circle` r=50 с `textPath`, 20px, смайл позиционирован абсолютно | SVG `textPath` по дуге r=46, 17px, `letter-spacing: 0.5px`; дуга выступает на 11px левее заголовка, как в макете | Параметры подобраны по совпадению с векторами Figma (bounding box ±2px). Бейдж `aria-hidden`: смысл передаёт скрытый h2 «Рецепт дня» | `text.svg` из архива — точная копия вектора из Figma, но текст становится картинкой: не выделяется и не переводится |
| Заголовок секции рецепта | Нет: заголовком секции служит название блюда | `h2.visually-hidden` «Рецепт дня», название блюда остаётся `h3` | Иерархия заголовков из практики №2 сохраняется, визуально как в макете | Сделать название блюда `h2` и убрать заголовок секции — меняет semantic map |
| h1 | Отсутствует: «Готовь и делись рецептами» — это `h2` | `h1` | Требование практики №2: один `h1` на странице | — |
| Кнопки hero | `<button>`; «+» — псевдоэлемент 26px | `<a>` (переходы, см. semantic map); «+» увеличен до 33px | Размер и положение «+» сверены с иконкой `add` в Figma (14×14px, ±1px) | Inline SVG-иконка `add` из Figma — точнее, но это ещё один ассет и разметка |
| Карточки категорий | `grid-template-columns: repeat(4, 278px)`, карточки — ссылки с hover-сдвигом | `repeat(auto-fit, minmax(min(16rem, 100%), 1fr))` из практики №4; на 1440 карточка 278.3px | Фиксированные 278px ломают сетку ниже 1200px. Целевых страниц категорий пока нет, поэтому карточки не ссылки | Вернуть ссылки и hover-сдвиг, когда появятся страницы категорий |
| Счётчики 356 / 35 минут | `position: absolute; right: 52px` внутри `.recipe` | `.recipe-meta` и `.recipe-card` в одной ячейке Grid (`grid-area: 1 / 1`), `justify-self: end`, `margin-right: 52px`; ниже 56rem — обычный поток | Без абсолютного позиционирования: элемент остаётся в потоке и не перекрывает контент на узких ширинах | Абсолютное позиционирование, как в архиве |
| Поиск | `padding: 0 158px` у секции, поле без рамки | `max-width: 884px; margin-inline: auto` у формы и тегов; поле без видимой рамки, с тенью `0 8px 42px rgba(34,39,47,.04)` из Figma | Ширина 884px задана один раз и не зависит от ширины контейнера | Как в архиве: через padding секции |
| `overflow-x: hidden` на `body` | Есть | Не используется | Практика №4 запрещает маскировать overflow; overflow отсутствует на всех проверенных ширинах | — |
| Размеры шрифтов | Фиксированные px, отдельный `@media (max-width: 1024px)` | Сохранены `clamp()` из практики №4; на 1440 значения равны макету | Плавное масштабирование без лишних breakpoints | — |
| Preloader, slider (Swiper), scroll-up, popup-формы, карточки из `data.json` | Есть | Не переносились | Это JavaScript и следующие темы курса (практики №5+) | Добавлять по мере прохождения тем |

## Тексты

Тексты приведены к макету, кроме явных опечаток:

- «Простые блюда» (в main оставался заголовок long-content теста практики №2);
- описания карточек и лид поиска без финальной точки, «найдем» вместо «найдём»;
- «На Праздник» и плейсхолдер «Название Блюда...» — с заглавной, как отображается в макете (в Figma на этих слоях стоит `capitalize`);
- не перенесены: «приготвления» (исправлено на «приготовления»), пропущенная запятая перед «которые», четыре точки в плейсхолдере.

## Известные расхождения на 1440px

| Место | Расхождение | Причина |
| --- | --- | --- |
| Форма поиска | Начинается с x=278 вместо 280 | В макете форма смещена от центра на 2px, в вёрстке она отцентрирована |
| Заголовки h1/h2 | Глифы на 1–2px выше | Округление `line-height` («normal» в Figma против числового значения) |
| Счётчики | Иконки смещены на 2–5px | В макете «35  минут» с двумя пробелами; в HTML пробелы схлопываются |
| Иконки сердца и таймера | Сердце чёрное, толще, чем в макете | Используются SVG из архива. Иконки Figma (`favorite_border`) из этого окружения скачать нельзя |
| Карточка «Простые блюда» | Первая строка описания на ~6px шире | Исправлена опечатка «приготвления» |
| Текст по дуге | Рисунок букв совпадает приблизительно | `textPath` рендерит шрифт браузером, в Figma — векторы |
