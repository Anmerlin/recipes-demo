# Анализ HTTP-запроса

Для практической работы рассмотрен запрос к публичной странице репозитория проекта на GitHub.

## Запрос

- URL: `https://github.com/Anmerlin/recipes-demo`
- Метод: `GET`
- Назначение: получение HTML-страницы репозитория в браузере.

## Что передает клиент

При открытии страницы браузер отправляет HTTP-запрос к серверу GitHub. В запросе присутствуют служебные заголовки, например:

- `Host` — домен сервера;
- `User-Agent` — информация о клиенте;
- `Accept` — форматы данных, которые клиент готов принять;
- `Accept-Language` — предпочитаемые языки;
- `Cookie` — может присутствовать для авторизованного пользователя.

Точные значения части заголовков зависят от браузера, операционной системы и состояния авторизации, поэтому здесь они не фиксируются как постоянные.

## Ответ сервера

При успешном открытии публичной страницы сервер возвращает HTML-документ и служебные заголовки ответа.

Ожидаемый успешный статус:

- `200 OK` — запрос обработан успешно, страница доступна.

Среди заголовков ответа обычно можно увидеть:

- `Content-Type` — тип возвращаемых данных;
- `Content-Encoding` — способ сжатия ответа, если используется;
- `Cache-Control` — правила кеширования;
- `Set-Cookie` — может использоваться сервером для сохранения состояния;
- заголовки безопасности, которые управляют политиками браузера.

## Вывод

При переходе по URL браузер формирует `GET`-запрос, сервер GitHub обрабатывает его и возвращает HTTP-ответ с кодом состояния, заголовками и HTML-содержимым страницы. Это базовый пример взаимодействия клиента и сервера по протоколу HTTP.
