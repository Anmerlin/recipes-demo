## Текущий этап

Практическая работа №6 — формы, валидация и загрузка данных через `fetch`. Ветка `lab/06-forms-fetch`.

Страницу нужно открывать через локальный HTTP-сервер (см. «Запуск»): при открытии `index.html` из файловой системы браузер блокирует `fetch` к `data/categories.json`, и категории не загрузятся.

### Сценарии практики №6

| Сценарий | Где | Что делает | Как проверить |
| --- | --- | --- | --- |
| 1. Категории из JSON | блок «Умная сортировка по тегам» | `fetch('data/categories.json')` через `async/await`, проверка `response.ok`, карточки из `<template>` с данными через `textContent` | Network: запрос `categories.json` → 200, 4 карточки. Network → Block request URL `categories.json` → «Не удалось загрузить категории…» и кнопка «Повторить»; снять блокировку → «Повторить» → карточки, фокус на заголовке раздела |
| 2. Вход и регистрация | кнопки «Войти» в header и hero | `<dialog>` с `showModal()`: Esc, клик по подложке и крестик закрывают окно, фокус возвращается на кнопку. Две формы с проверкой полей: `required`, `minlength`, `pattern`, `type="email"`, совпадение паролей и имя из пробелов — через `setCustomValidity()` | пустая отправка → сообщения у каждого поля, фокус на первом ошибочном; исправление поля убирает сообщение сразу; верные данные → статус «Форма заполнена верно…», пароль очищен |
| 3. Запомнить логин | флажок в форме входа | при отправке с флажком логин записывается в `localStorage` (`recipes:login`), без флажка — удаляется; при следующем открытии логин подставлен, фокус на пароле | Application → Local Storage: ключ `recipes:login`; перезагрузка → «Войти» → логин на месте |
| 4. Добавить рецепт | раздел `#add-recipe` (кнопка «Добавить рецепт» в hero) | проверка полей (текст, select, number, radio, textarea, file) и правил без HTML-атрибутов: название не из пробелов, минимум два ингредиента, фото до 2 МБ. Данные собираются из `FormData` в объект и показываются как JSON | пустая отправка → ошибки и фокус на «Название»; время 7 → «кратно 5»; один ингредиент → «Нужно минимум два…»; верные данные → JSON с `time` числом и `ingredients` массивом; «Очистить» убирает сообщения и JSON |

Пароли нигде не сохраняются и не выводятся. Проверка в браузере — подсказка пользователю, а не защита: логин, пароль и данные рецепта должен заново проверить сервер. Сервер и база данных — темы следующих занятий; тогда `CATEGORIES_URL` и `action` форм будут указывать на настоящие адреса API.

### Решения практики №6

- Общие функции проверки (`getErrorMessage`, `validateField`, `validateForm`, `enableLiveValidation`) используются всеми тремя формами. Формы помечены `novalidate`: правила остаются в HTML-атрибутах, а сообщения показывает скрипт рядом с полем — через `aria-invalid` и `aria-describedby`, а не всплывающими подсказками браузера.
- Ошибку поля показываем после первой попытки отправки, а дальше пересчитываем при каждом вводе: пока пользователь впервые заполняет поле, его не перебивают сообщениями.
- Модальное окно — нативный `<dialog>`: удержание фокуса, Esc и возврат фокуса браузер делает сам. В исходном проекте был `div` с `hidden`, без удержания фокуса.
- В исходном проекте логины и пароли были записаны прямо в JavaScript, а после «входа» в header вставлялось имя через `insertAdjacentHTML`. Здесь этого нет: проверять пароль на клиенте бессмысленно (код открыт в Sources), а вставка пользовательской строки как HTML небезопасна.
- Карточки категорий в исходном проекте собирались строкой через `insertAdjacentHTML`; здесь — клонирование `<template>` и `textContent`, и добавлены состояния загрузки, ошибки и пустого списка.
- Без JavaScript вместо категорий показывается сообщение в `<noscript>`. Кнопки «Войти» без JavaScript не работают — так же, как прежняя ссылка на несуществующий `#login`.

## Практика №5 — JavaScript: DOM, события и состояние интерфейса

Ветка `lab/05-js-dom`, слита в `main` (PR #8).

JavaScript подключён одним внешним файлом `scripts/script.js` с `defer`. Каждый блок сначала проверяет, что нужные элементы найдены, и только потом назначает обработчики.

### Сценарии

| Сценарий | Control | Начальное состояние | Событие | Что меняется | Как проверить |
| --- | --- | --- | --- | --- | --- |
| 1. Избранное (основной) | `<button aria-pressed>` с иконкой сердца в блоке рецепта | не в избранном, счётчик 356 | `click` (мышь, Enter, Space) | состояние `isFavorite` и `count` → класс `recipe-meta__favorite--active`, `aria-pressed`, текст счётчика | 356 → 357 → 356; Elements: класс и `aria-pressed` меняются вместе со счётчиком |
| 2. Фильтр тегов (второй) | поле `#recipe-query` | все 4 тега видны | `input` | тегам без совпадения добавляется `recipe-search__tag--hidden`; при нуле совпадений — «Теги не найдены» в `role="status"` | пустой ввод → все теги; «ры» → Рыба; «  МЯСО » → Мясо; «xyz» → сообщение; очистка → все теги |
| Header | — | прозрачный фон, на месте | `scroll` | после прокрутки на высоту header — класс `site-header--scroll`; при прокрутке вниз — `site-header--hidden` (уезжает вверх), при прокрутке вверх класс снимается | Elements: классы меняются при прокрутке; Tab по ссылке в скрытом header возвращает его (`:focus-within`) |
| «Наверх» | `<button>` в правом нижнем углу | скрыта (`visibility: hidden`, вне Tab-порядка) | `scroll`, `click` | после прокрутки на высоту окна — `scroll-up--show`; клик прокручивает наверх и переносит фокус на логотип | Tab до кнопки → Enter → страница наверху, фокус на логотипе |
| Прелоадер | — | спиннер поверх страницы | `load` | класс `preloader--hidden`, после fade-out элемент удаляется; header получает `site-header--enter` и выезжает | Network → throttling: прелоадер держится до конца загрузки; Network → Block request URL `script.js`: через 5 секунд прелоадер скрывает CSS |

Сценарии 1 и 2 — обязательные сценарии практики №5. Header, «Наверх» и прелоадер перенесены из исходного проекта как дополнительные эффекты.

### Отличия от исходного скрипта

- Избранное: состояние читается из разметки, одна функция `renderFavorite()` обновляет класс, `aria-pressed` и счётчик; вместо `children[0]` — хуки `data-favorite-toggle` и `data-favorite-count`.
- Фильтр: добавлены `trim()` и сообщение при отсутствии совпадений.
- Header: состояние синхронизируется сразу при загрузке (страница может открыться прокрученной), обработчик `scroll` пассивный, `console.log` в обработчике убран. Высота header передаётся в CSS через `--header-height` (`ResizeObserver`), чтобы на узких экранах fixed header не перекрывал контент и якорные переходы. На узких экранах fixed header занимает около четверти окна, поэтому при прокрутке вниз он скрывается, при прокрутке вверх возвращается. Выезд при загрузке запускает JS классом `site-header--enter`, поэтому без скрипта header просто стоит на месте.
- «Наверх»: прокрутка использует CSS `scroll-behavior`, поэтому при `prefers-reduced-motion` она мгновенная; фокус переносится на логотип.
- Прелоадер: убирается по событию `load`, а не через `setTimeout(3000)`; контент не скрывается через `display: none`; без JavaScript прелоадер отключён через `<noscript>`. Если скрипт не загрузился (404, ошибка сети), через 5 секунд прелоадер скрывает CSS-анимация `preloader-fallback`, поэтому страница не остаётся закрытой.

## Практика №4 — CSS Grid, responsive layout и transition

Реализовано:

- семантическая HTML-структура предыдущих практик сохранена;
- `css/style.css` остаётся единой точкой входа;
- категории переведены на реальный CSS Grid;
- карточная сетка использует `auto-fit + minmax()` и меняет число колонок по доступному пространству;
- hero и блок рецепта используют Grid и переходят в двухколоночное состояние только там, где композиции достаточно места;
- breakpoint `56rem` связан со сменой layout state, а не с названием устройства;
- Flexbox сохранён в одномерных задачах: header/navigation, кнопки, meta, search form и footer;
- размеры контейнера, заголовков и изображений остаются fluid;
- добавлены `min-width: 0` и `overflow-wrap` там, где длинный контент может влиять на sizing;
- `overflow-x: hidden` для маскировки проблем не используется;
- добавлены transition для конкретных properties;
- заметный `:focus-visible` сохранён;
- для пространственного motion предусмотрен `prefers-reduced-motion`;
- контентные изображения используются только как PNG и не конвертируются.

## Структура CSS

HTML подключает один файл: `css/style.css`.

`style.css` импортирует файлы в следующем порядке:

1. `fonts.css` — web-fonts;
2. `normalize.css` — нормализация;
3. `base.css` — tokens, box model, базовые элементы и fluid container;
4. `typography.css` — кнопки и общая типографика;
5. `section.css` — заголовки и описания секций;
6. `logo.css` — логотипы;
7. `header.css` — header и navigation;
8. `promo.css` — hero;
9. `card.css` — Grid карточек категорий;
10. `recipe.css` — рецепт дня;
11. `search.css` — поисковая секция;
12. `form.css` — форма поиска и общие поля форм (подписи, ошибки, подсказки, статус);
13. `dialog.css` — окно входа и регистрации на `<dialog>`;
14. `add-recipe.css` — раздел «Добавить рецепт» и предпросмотр JSON;
15. `footer.css` — footer;
16. `scroll-up.css` — кнопка «Наверх»;
17. `preloader.css` — прелоадер;
18. `responsive.css` — content-driven breakpoint (desktop-состояние: отступ под header, волны, раскладка рецепта) и reduced-motion override.

Обязательного отдельного responsive-файла в курсе нет; здесь он сохранён как небольшой завершающий модуль, потому что переключение состояния затрагивает несколько компонентов.

## Запуск

Проект не использует сборщик.

1. Клонировать репозиторий.
2. Запустить локальный HTTP-сервер в папке проекта: расширение Live Server в VS Code, `npx serve` или `python -m http.server 8000`.
3. Открыть адрес сервера (например, `http://localhost:8000/`) — не файл через `file://`, иначе `fetch` не загрузит `data/categories.json`.
4. Для проверки открыть Chrome DevTools.

Для практики №4 полезно проверить:

- плавный resize от узкой до широкой ширины;
- Grid overlay для `.categories__list`;
- Styles/Computed для Grid и media query;
- длинный заголовок/описание;
- Tab-navigation и `:focus-visible`;
- отсутствие необъяснимого horizontal overflow;
- `prefers-reduced-motion: reduce`.

Контрольные ширины 390 / 768 / 1280 можно использовать для проверки, но они не являются значениями обязательных breakpoints.

Для практики №5:

- Network: `script.js` загружается без 404;
- Console: нет ошибок;
- Elements: при клике по сердцу меняются класс, `aria-pressed` и счётчик; при вводе в поиск — классы тегов;
- Sources: breakpoint в обработчике `click` избранного или в `filterTags`;
- клавиатура: Tab до сердца, Enter/Space; Tab до «Наверх» после прокрутки.

Для практики №6:

- Network: `categories.json` → 200, тип `fetch`; при блокировке запроса — сообщение и «Повторить»;
- Console: нет ошибок при успешной загрузке; при заблокированном запросе — одна запись `console.error` с причиной;
- Elements: у ошибочного поля `aria-invalid="true"`, текст ошибки связан через `aria-describedby`;
- Application → Local Storage: ключ `recipes:login` появляется только при отмеченном флажке;
- Sources: breakpoint в `loadCategories` (после `await`) и в обработчике `submit` формы рецепта — видно объект из `collectRecipe()`;
- клавиатура: Tab до «Войти» → Enter → фокус в поле, Tab не выходит из окна, Esc закрывает и возвращает фокус на «Войти».

## Использование AI

Практика №6: AI использовался для реализации четырех сценариев по исходному проекту и темам лекции №6 и для поиска пограничных случаев проверки: пробелы вместо значения (`required` их пропускает), пустые строки в ингредиентах, файл больше лимита, ответы 404/500 у `fetch`, запрет доступа к `localStorage`. Набор сценариев и отказ от проверки паролей на клиенте определил автор. Проверка: Chromium на ширинах 360 и 1440, сценарии мышью и клавиатурой, блокировка запроса, Local Storage, Nu HTML Checker и CSS-валидатор — 0 ошибок.

Практика №5: AI использовался для переноса пяти блоков из `scripts/script.js` исходного проекта на текущую разметку и сверки результата с критериями практики №5. AI предложил: заменить setTimeout-прелоадер на событие `load`, синхронизировать header при загрузке, измерять высоту header через `ResizeObserver` (первый вариант с `resize` давал устаревшую высоту на 360px до загрузки шрифтов — найдено при проверке), переносить фокус после «Наверх». Решения по header (fixed на всех ширинах, как в исходном проекте), прелоадеру и сообщению «Теги не найдены» приняты автором. Проверка: Chromium на ширинах 320–1920 (сценарии, клавиатура, Console, Network, overflow), режим без JavaScript, `prefers-reduced-motion`, Nu HTML Checker и CSS-валидаторы.

Практика №4: AI использовался как вспомогательный инструмент для сопоставления критериев практики №4 с текущим demo-проектом, выбора Grid/Flexbox, проверки responsive strategy и поиска рисков overflow.

В этой итерации предложения AI ограничены темами лекции №4: Grid, intrinsic/fluid sizing, media queries, transition и reduced motion. JavaScript и другие следующие темы намеренно не добавлялись. Результат проверяется по фактическому CSS и поведению layout, а не принимается автоматически.
